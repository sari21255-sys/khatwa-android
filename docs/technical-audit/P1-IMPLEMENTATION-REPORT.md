## 5. P1-2 هوية متحقَّق منها

**الربط بالحسابات الحالية:** التطبيق يستعمل جلسة Supabase الموجودة أصلًا للمجتمع. حساب الوسيط القديم ينتقل بالنقل اليدوي: حامل الرمز على جهازه، أو بالدخول بالبريد وكلمة المرور من الإعدادات (MIG-04). اللقطة القديمة تُدمج سجلًا بسجل (MIG-01) ويتكرر النقل دون تضاعف (MIG-02) ثم تُجمَّد (MIG-03) ولا تُحذف.

**التحقق على الخادم:**
- الوسيط: توقيع JWT (ES256/RS256 عبر JWKS أو HS256)، الانتهاء، المُصدِر، الجمهور، الدور، `sub`. يرفض `alg=none` وخلط HS256 بالمفتاح العام.
- Postgres: كل دالة تستدعي `assert_session()` (مستخدم موقّع وجلسته قائمة في `auth.sessions`)؛ لا وصول مباشر للجداول (RLS مفعّل بلا سياسات + سحب الصلاحيات).
- الحصص: `consume_quota` ذرّية. الفشل في الوصول إلى Supabase يُرفض (503) لحماية التكلفة.

| الاختبار | النتيجة |
|---|---|
| 12 اختبار توقيع/ادّعاء للـJWT (منتهٍ، مفتاح آخر، iss/aud/role/sub، none، خلط HS256، kid مجهول) | PASS (`worker-p1.log`) |
| رمز الوسيط القديم لا يعطي هوية للذكاء ولا كتابة في وضع supabase | PASS |
| جلسة مُبطلة: Postgres يرفض المزامنة والحصة فورًا (SQL + SES-02 + اختبار الوسيط) | PASS |
| انتهاء الرمز: تجديد تلقائي (SES-01)؛ انقطاع شبكة وقت التجديد لا يُخرج المستخدم (SES-03) | PASS |
| عزل الحسابات (SQL + RS-08) | PASS |
| حد المستخدم: 40 طلبًا متوازيًا ← 5 مقبولة بالضبط؛ الحد الكلي: 60 طلبًا من 4 مستخدمين ← 7 | PASS (جلسات psql حقيقية) |
| 30 طلبًا متزامنًا عبر الوسيط ← 3 مقبولة | PASS |
| ساعة جهاز متقدمة بأيام ترفضها المزامنة (CLK-01) | PASS |

**ثغرة وُجدت وأُصلحت أثناء العمل:** `SB.fresh()` كان يُخرج المستخدم عند أي فشل في تجديد الرمز حتى لو كان الانقطاع شبكيًّا. صار يُخرجه فقط عند رفض الخادم.

## 7. الترحيل والتراجع

مفصّلان في `P1-DESIGN.md`. جُرّب التراجع على بيانات اصطناعية: `04_rollback.sql` (بيانات المجتمع تبقى، `delete_my_account` يعمل، إعادة تطبيق الهجرة تنجح)، وRB-01 (إزالة `sbUrl` من التطبيق تُبقي بيانات الجهاز سليمة). الفرق بين الحالتين: سجلات السحابة تضيع بتراجع قاعدة البيانات، وأجهزة المستخدم تحفظ نسخها وتُعيد رفعها.

## 8. الأداء

حالة اصطناعية بنحو أربع سنوات استعمال (700 كيلوبايت، 12 ألف سجل): تفكيك ووسم الحالة 26–27 مللي ثانية، وسجل المزامنة المحلي `fit_rs` يشغل 740 كيلوبايت إضافية في `localStorage`. الرفع الأول 25 دفعة.

## 9. ما لم يُنفَّذ

| البند | السبب |
|---|---|
| Supabase الحقيقي (تسجيل، RLS تحت PostgREST، `auth.sessions`، مطالبة `session_id`، أكواد الأخطاء) | لا مشروع. المحاكاة وفق التوثيق وفق Postgres حقيقي لكن بلا GoTrue ولا PostgREST |
| Cloudflare الحقيقي (JWKS، حدود Workers) | لا حساب |
| Health Connect والإشعارات والتنقل على جهاز | لا جهاز |
| ترويسات Netlify الفعلية | لم يُنشر |
| فحص أن مفتاح AAB هو مفتاح الإنتاج | لا يمكن من CI |
| Lighthouse وnpm audit وفحص الاعتماديات | لا وصول للشبكة من بيئتي |
| ترجمة النصوص الجديدة إلى الإنجليزية في وضع «عربي + English» | لم تُضف إلى `ENT` |

## 10. مخاطر متبقية

- النشر بلا Supabase يُبقي المزامنة القديمة (لقطة كاملة، آخر كتابة تفوز) ولا يعالج فقد البيانات.
- ساعة الجهاز مصدر الوقت. انحراف دقائق قد يقلب تعارضًا متزامنًا (انحراف أيام يُرفض).
- مستخدم واحد يستطيع استنزاف السقف الكلي للذكاء (حدّه الفردي 100 يوميًا) حتى تُضاف خطوة تحقق بريد.
- مشغّل الخدمة يرى سجلات المستخدمين بحكم صلاحية قاعدة البيانات (مكتوب في سياسة الخصوصية).
- رمز دخول مسروق يعمل حتى انتهائه أمام الفحص المحلي للتوقيع في الوسيط (لكن Postgres يرفضه عند إبطال الجلسة).
- سجل `fit_rs` في `localStorage` يضاعف تقريبًا حجم ما يُخزَّن محليًا (حدّ المتصفح نحو 5 ميغابايت).
